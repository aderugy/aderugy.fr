### Le problème

Ce corpus contient des dizaines de blocs Python, chacun suivi de « Sortie
obtenue ». Ces sorties ont une prétention précise : **quiconque exécute ce
code doit obtenir ce texte**. Or trois choses s'y opposent, et aucune ne se
voit dans le code.

- **Le hasard.** Une simulation tire des nombres pseudo-aléatoires. Sans
  précaution, chaque exécution en tire d'autres, et le résultat change.
- **L'environnement.** Le même code, avec une autre version de Python ou de
  NumPy, peut donner un autre résultat — ou ne plus s'exécuter. Le bouton
  « exécuter » de ce site fait tourner Python **dans le navigateur**, avec une
  version de NumPy qui n'est pas celle qui a produit les sorties publiées.
- **L'arithmétique.** Les nombres réels de la machine sont des flottants. Le
  même calcul, fait dans un autre ordre, ne donne pas exactement le même
  résultat — et une bibliothèque peut changer l'ordre sans prévenir.

À cela s'ajoute un piège propre aux notebooks : l'état caché laissé par les
cellules exécutées dans le désordre.

Ce nœud ne contient presque pas de mathématiques, à une exception près — la
borne d'erreur d'une somme en flottants. Il contient en revanche ce qui rend les
vérifications numériques du parcours dignes de confiance. Une simulation qu'on
ne peut pas refaire ne vérifie rien.
